# 本地可视化简历编辑器

v0.5 编辑内核复用 MIT 许可的 Tiptap 3.32.0，前端已预打包，使用者无需 Node。编辑器适合已经确定内容、希望自己改文字并查看排版的用户。它复用 `build.py` 和验证流程，预览来自实际 PDF 的逐页 PNG。它不会自动润色、虚构经历或替用户进行内容核实，也不会把 HTML 预览当成最终 PDF。

## 启动

先运行 `scripts/setup.py` 自动安装 Python 依赖、字体和编译器，并完成一次样例构建（见 [environment.md](environment.md)），再运行：

```sh
.venv/bin/python skills/latex-resume/scripts/preview.py \
  --workspace private/editor
```

路径以仓库根目录为例；安装为 skill 后请改成实际安装位置。Windows 使用 `.venv/Scripts/python.exe`。默认端口是 8765，启动后通过系统默认外部浏览器打开页面。只监听 `127.0.0.1`，不是公网托管服务。不要把个人编辑工作区提交到仓库。

首次载入虚构中文示例；重复使用相同工作区则读取已保存的 `resume.md`。导入自己的 Markdown 时可指定：

```sh
.venv/bin/python skills/latex-resume/scripts/preview.py \
  --source private/resume.md --workspace private/editor-import --pages 1
```

`--source` 将内容复制为工作区草稿，不回写输入文件。工作区存在不同内容时会报错，避免覆盖；省略 `--source` 继续原草稿，或选择新工作区。

可选参数：

- `--pages 1`：预期页数，允许 1–20；检查不符会报错，不静默删内容或缩字。
- `--port 0`：选择空闲端口，终端会打印实际地址。也可指定固定端口。
- `--no-open`：只启动服务并打印 URL，由用户自行在外部浏览器打开。

终端需保持运行；按 Ctrl+C 停止服务。不要为停止本任务而关闭其他浏览器窗口或共享进程。

## 编辑、图标与生成

1. 左侧像简历一样直接点击文字修改，无需学习 Markdown。点击「导入」可载入符合 [source-format.md](source-format.md) 的旧原稿；不支持的格式会拒绝导入并保留当前内容。
2. 选中文字后点击 **B** 加粗，或选择「字号」（8–32 pt，0.5 pt 步进）；「跟随模板」清除局部字号。顶部「全文字号」调整正文基准大小（8–18 pt，默认10.5 pt）。
3. 「＋ 添加内容」提供章节、经历、要点、普通文字。经历条目有机构、职位、日期三个编辑字段，Tab 切换字段。粘贴只保留文字，格式通过工具栏调整。
4. 点击「插入图标」，搜索北邮、GitHub 等名称，可按学校/公司与技术筛选。选中一个图标即插入光标位置；点击已插入的图标后，通过工具栏改大小（8–48 pt，0.5 pt 步进）。图标身份与来源见 [logos.md](logos.md)。
5. 编辑停顿 **650ms** 后自动保存并调用 LaTeX。编译需要数秒，首次资源下载可能更慢。「更多设置」可调整预期页数或手动重新生成。
6. 左侧读取所选 LaTeX 模板的页边距、标题字号、间距与颜色，使用相同 Noto 字体和 A4 页面；单双栏和经历排列跟随模板，两侧统一缩放（含100%）。校徽保留原始宽高比，字号与图标尺寸按 TeX pt 换算。浏览器与 TeX 的断行/分页算法不同，不承诺逐像素一致；右侧是实际 LaTeX PDF 页面，最终排版和分页以右侧为准。当前版本校验通过后，右上角可导出 PDF；「更多导出」提供 PNG、Markdown。单页 PNG 直接下载，多页打包 ZIP。

Markdown 原稿保存正文、加粗、局部字号、图标大小。全局字号、模板、预期页数在工作区 `editor-settings.json` 中；迁移完整工作区时一并保留。
图标通过清单 ID 解析本地 SVG，构建时转换为矢量 PDF；不运行远程图标脚本，也不从 CDN 查找缺失 ID。产品标识不能冒充公司标识，添加图标也不证明任职或技能。

## 保存与过期结果

「导入」和输入文字先修改编辑器；默认停顿 650ms 后保存并生成。全文字号、模板与预期页数保存为工作区 `editor-settings.json`，重启同一工作区可恢复。关闭页面前查看保存状态；连接中断或未完成保存时，导出 Markdown 保留当前正文。编辑器不承诺浏览器崩溃后的未保存内容恢复。

编译前会写入 `resume.md`，已有草稿备份为 `resume.previous.md`（单个上一版本，不是完整历史）。语法错误、编译失败或超时不应丢掉已写入的草稿。重新运行同一工作区可继续编辑。

每次构建使用独立 `builds/<构建ID>/`。编辑文字、字号或预期页数后，旧预览标为过期，旧 PDF / PNG 导出立即禁用；失败时可保留上次成功预览供比较，但它不代表本轮生成成功。编译过程中又修改内容时，前一快照的结果不能替代最新编辑内容。

## 排错

- **依赖未就绪：** 先完成 `setup.py` 和终端样例构建。首次字体准备或 Tectonic 资源下载可能耗时，编辑器构建有 600 秒超时。
- **语法报错：** 展开详细信息，交由 agent 按提示检查原稿。只支持约定子集，不支持一般 Markdown 图片、HTML 或原始 TeX；未知图标 ID 也会失败。
- **页数或文字验证失败：** 检查正文和预期页数，合理精简或明确调整页数，不能跳过验证冒充成功。
- **地址被占用：** 使用 `--port 0` 或另一个空闲端口，不终止不属于本任务的进程。
- **连接断开：** 确认终端服务仍在运行；浏览器未保存修改先下载 Markdown。重新启动时保留原工作区。

页面与接口仅面向本机使用，带有 Host/Origin 校验和会话令牌检查。简历正文在浏览器与本机服务之间处理；首次依赖下载仍可能联网。该模式不提供多人协作、远程账户或公网访问隔离保证。

## 维护与分发

前端源码位于仓库 `frontend/editor.js`、`rich-editor.js`、`document.js`；维护者运行 `npm ci`、`npm run build`、`npm test`。终端使用者直接运行已打包编辑器，不需要 Node。源码 ZIP 应包含 `assets/editor/bundle.js`、`bundle.css`、完整 frontend licenses 和 notices。选型与设计见仓库 `docs/LIVE-EDITOR-RESEARCH.md`、`docs/TEA-DESIGN.md`。

## 切换模板

顶部「切换模板」打开缩略图面板：经典单栏、简洁单栏、彩色双栏。缩略图来自同一份虚构中文 Markdown 的真实 LaTeX PDF。选择后保留全部文字和字号，立即使旧导出过期，并自动按新模板重新编译。新的 PDF/PNG 只在新模板通过全文、页数与版面校验后开放。

模板选择与字号/页数一起保存到 `editor-settings.json`，重启同一工作区可恢复；导出 Markdown 包含局部格式，不包含模板和全局设置。CLI 使用 `build.py --template minimal`（默认 `classic`）。已有旧工作区缺少模板字段时按 `classic` 读取。详见 [模板来源与适配](templates.md)。
