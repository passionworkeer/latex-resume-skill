# 简历编辑器视觉与交互约定

核验日期：2026-10-21。目标为清爽、精确、操作一致的腾讯云控制台式工作台：左侧实时编辑，右侧实际排版预览，PDF、PNG、Markdown 分别导出。

## 选型与公开复用边界

本轮保留原生 HTML/CSS/JavaScript 工作台，v0.5 编辑内核复用 MIT 许可的 Tiptap；视觉与交互独立实现。无需为两个面板、工具栏和导出按钮引入 React。以下是本项目建议值，**不是经过核验的 Tea 官方 design token**，也不是 Tea 样式文件的复制品。

- [Tea 官网](https://tea.tencent.com/)与[组件目录](https://tea.tencent.com/component)可用于理解一致的控件语义；[按钮](https://tea.tencent.com/component/button)、[间距](https://tea.tencent.com/component/space)、[状态](https://tea.tencent.com/component/status)、[布局](https://tea.tencent.com/component/layout)是相关参考入口。本次检索工具无法读取这些动态页面，不能声称已核验官网当前像素值或 API。
- [公开 tea-component 仓库](https://github.com/tea-design/tea-component)介绍 React 组件和 CSS 导入；[npm 页面](https://www.npmjs.com/package/tea-component)及[registry 元数据](https://registry.npmjs.org/tea-component/latest)当前显示版本 2.8.0、`license: UNLICENSED`、React / React DOM >=16.8.0。因此不将包、打包 CSS、字体或图标引入本开源项目。公开可访问不等于存在开源再分发授权。GitHub 页面未呈现许可文件；GitHub license API 本次受限，不能推断拥有额外许可。
- 不复制私有业务组件、内部 npm 包、公司主题包、截图或私有设计资源。只读研究既有工作台中的复用原则和状态处理方式；本仓库不保存内部源码、内部链接清单或内部实现片段。
- 若未来确需 React，可另评估[腾讯 TDesign](https://github.com/Tencent/tdesign)及其[React 实现](https://github.com/Tencent/tdesign-react)，按实际版本核验 MIT 许可并保留通知。TDesign 与 Tea 是不同的组件体系，不应混称。

## 工作台布局

1. 顶部 64px 白色应用栏：产品名、当前文件名和简短本机状态在左侧；右侧提供三个明确操作「导出 PDF」「导出 PNG」「导出 Markdown」。PDF 可为主要按钮，另两个为有边框次按钮。保持三个操作独立，避免将 Markdown 藏入不明确的「下载」按钮。
2. 内容区距页面边缘 24px，面板间距 16px。桌面使用两栏，左侧约 46%、右侧约 54%，两个面板至少约 360px。右侧是实际生成的页面，保持纸张长宽比并居中展示。
3. 面板标题栏高约 48px：左面板「Markdown 编辑」，右面板「排版预览」。标题旁可显示文件名与页数；避免大段营销文字挤占编辑空间。
4. 编辑工具栏只放「打开 Markdown」「插入图标」和必要格式帮助；页数、实时预览开关放入紧凑的设置行。不要重复摆放三个导出入口。
5. 右侧预览使用浅灰画布与白纸、细阴影；画布独立滚动。缩放控制若存在，应明确「适应宽度」与百分比，不用浏览器缩放替代。
6. 窄屏切换为上下排列，编辑在上，预览在下；顶部操作允许换行。不要给整个页面强制宽于视口的最小宽度。更窄时按钮保留完整可理解名称。

## 实时编辑与导出状态

- 编辑后约 600–900ms 防抖生成；编辑输入始终可用。一次只运行一个排版任务，输入变化时合并到最新版本，丢弃迟到结果，防止预览被旧内容覆盖。
- 明确区分「草稿已保存」「正在排版」「预览已更新」「排版失败」。构建中保留最近成功预览，并显示它尚未反映最新编辑；错误显示可读原因和重试操作，详细日志折叠。
- 如果实时预览默认启用，页脚及空状态应说明自动更新；快捷键可以保留为立即更新。所有文案必须与实际保存和生成时机一致。
- PDF 与 PNG 使用最新成功生成的相同内容版本；旧结果尚未更新时禁用相关导出并说明正在更新，或明确标记导出的是上一次结果。Markdown 直接导出当前文本，不依赖 LaTeX 生成成功。
- PNG 多页行为需明确：显示「导出 PNG（N 页）」并逐页下载或提供一个包含全部页的归档；不能静默仅导出第一页。
- 初始加载、空文档、服务不可达、排版失败、无可导出结果都要有对应状态。通知不应阻挡输入；`role=status` 用于温和进度，`role=alert` 用于实际失败。

## 实现验收建议

检查 1440px、1024px、390px 视口，键盘操作与焦点可见性；用长中文、英文、多个页面验证溢出、滚动及预览比例。验证连续输入不会产生旧预览覆盖；三个导出按钮分别生成有效 PDF、包含全部页的 PNG 和与当前编辑一致的 Markdown。运行现有编辑器测试并查看真实页面，不能只依据 CSS 静态检查。

## 排版来源更新

2026-10-21 用户确认：LaTeX 是唯一排版来源。Markdown 编辑器只编辑正文与加粗，正文字号选择为 9、9.5、10、10.5（默认）、11、11.5、12 pt。编辑后自动编译 LaTeX，再将真实 PDF 页渲染为右侧 PNG 预览；PDF 和 PNG 导出必须对应同一次成功编译。取消浏览器排版或浏览器打印 PDF 的替代路线，也取消单独的高级 LaTeX 区。预览工具区提供字号、预期页数与「重新生成」，状态使用「正在同步」「已同步」「待更新」。连续编辑、失败与旧版本处理仍遵循上文规则。
